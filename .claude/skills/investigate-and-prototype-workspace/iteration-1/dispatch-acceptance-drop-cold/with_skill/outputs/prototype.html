REAL DATA — from the code

The mechanism, read from config.py / history.py / routing.py

A decline or a timeout
both subtract 0.12 from a responder's acceptance score. Identical penalty — the code doesn't distinguish them.
→
Nothing decays it back
Wen's 2019 TODO asked whether the score should ease toward neutral over time. Still unresolved — it never does.
4.2 (12 Aug): proximity weight 0.45→0.60
acceptance weight 0.40→0.25. A lower score now costs a responder more in the ranking than it used to.
→
A responder ranked low gets offered less
which can't recover their score, because the only way up is accepting an offer — and they're not being offered one.
